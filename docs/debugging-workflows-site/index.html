Workflow 01

Simple sign-in debugging

WebStorm React Native + Xcode on an iPhone

Ready to use

Prepare the React Native session

  1. In WebStorm’s GetBored React Native configuration, turn Build and launch application off. WebStorm will manage the JavaScript session while Xcode builds and launches the native iOS app.
  2. Turn Hermes engine is enabled on and keep the bundler at localhost:8081.
  3. Confirm Start React Native Bundler appears under Before launch, select GetBored React Native in the toolbar, and click Run. It is a before-launch task—not a separate button. WebStorm starts Metro, the development server that builds the JavaScript bundle and serves it to the debug app.
  4. Wait until WebStorm’s React Native tool window reports that Metro is ready on port 8081, and leave it running. Do not start a second bundler.
  5. In Xcode, open GetBoredIOS.xcworkspace, choose the GetBored iOS scheme and the connected iPhone, and make sure the scheme’s Run action uses the Debug build configuration. Click Xcode’s Run button. Xcode builds, installs, and attaches to the Swift app; the running debug app then loads its JavaScript from Metro.

Set breakpoints in order

Use one executable breakpoint per function and follow a single credential submission across JavaScript, the native bridge, and the network client.

  1. src/screens/HomeScreen.tsx:285 — submit sends the normalized credentials to onSignIn.
  2. src/hooks/useAccount.ts:175 — signIn creates the native bridge operation and passes it to runSignIn.
  3. src/hooks/useAccount.ts:159 — runSignIn invokes that bridge operation with await start().
  4. src/native/AccountBridge.ts:31 — AccountBridge.signIn executes the JS-to-native native.signIn call.
  5. Sources/iOS/App/AccountModule.swift:30 — AccountModule.signIn calls the shared authenticate function.
  6. Sources/iOS/App/AccountModule.swift:91 — authenticate executes the decoded APIClient.shared.request call.
  7. Sources/iOS/App/APIClient.swift:328 — request calls the raw send function.
  8. Sources/iOS/App/APIClient.swift:180 — send executes the actual URLSession network request.

Fallback: if a JavaScript breakpoint does not bind in WebStorm, open React Native DevTools and attach there; keep the native Xcode breakpoint sequence unchanged.
