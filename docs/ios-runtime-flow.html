iOS Runtime Map

How the GetBored iOS app boots, bridges to native, and filters Safari

Read every screen the same way: visible card → RN component → hook (state machine) → JS bridge → Swift @objc module → platform (NEFilter / CKContainer / App Group) → KMP decision → state update → re-render. The one fact that explains the whole app: Swift only collects bytes and converts types — every decision lives in the Kotlin GetBoredSharedCore, reached through the single seam KMPDecisionCoreAdapter.

Every interaction in the app follows the same six beats. Keep this in mind for all the lanes below; the action matrix at the end applies it to every control.

Bridge lanes — reading native through classic RN modules

NativeModules · RCT_EXTERN

Two read pipelines feed the UI, and both take the identical shape: a polling hook calls a JS *Bridge.ts object, which marshals across the classic RN bridge (.m RCT_EXTERN_MODULE) into a Swift @objc module that does the platform I/O, then funnels every decision through KMPDecisionCoreAdapter → Kotlin GetBoredSharedCore before the Promise resolves and React re-renders. Swift collects; Kotlin decides.

Status read — useFilterStatus → StatusCard / DeviceRegistrationCard

Defaults read — useAppGroupDefaults → AppGroupDefaultsCard

Cross-lane link — the Flow Log card is a live tail of the Safari relay decisions (Section 5) · red = writes to / reads from the shared App Group key

The single most interesting wire in the app: Swift never tells the UI about a relay decision — it just appends a line to this one App Group key, and the polling defaults card surfaces it. Read the arrow left to right: a Safari flow is allowed/blocked → the event is written → the card tails it.
Read = poll + setState union Both reads are a discriminated union {kind:'loading'|'ready'|'error'} driven by a setInterval (status 5000ms, defaults 3000ms). Every tick re-runs load(), re-marshals the bridge, and calls setState — the UI is a projection of the latest native snapshot.

Safari parent-child pipeline

NEAppProxyProvider · per-app VPN

A Safari page's child resources reach the App Group, then the Safari-only per-app VPN relays or drops each TCP flow — but Swift never decides. It collects the active page context + rule snapshot and asks Kotlin SafariAppProxyPolicy for the verdict. Two sibling NEFilter extensions enforce the same context for every other app.

All three enforcement points read the SAME App Group and funnel through the SAME KMPDecisionCoreAdapter → GetBoredSharedCore. Each enforcer collects bytes/flows + the shared context, then asks Kotlin for the decision:
  • App Proxy: Safari TCP flows.
  • Data Provider: all-app content filter.
  • Control Provider: escalated blocks.
  • Division of labor: Swift owns only platform I/O; if the KMP framework is absent the adapter calls kotlinCoreUnavailable() → preconditionFailure.
Dropped for space: the TCPRelay internals — the bidirectional byte-pump (readFromFlow/readFromConnection), TCP half-close on EOF, makeEndpoint parsing, and the ARC retain via relays[id] — are collapsed into the single "relay or drop" verdict node. Full detail at SafariAppProxyProvider.swift:189-442.

CloudKit · App Group

Two persistence flows. The PR #14 companion-device registration writes a device entry into a private CloudKit record; the rule-state loop keeps IOSRuleStore (the App Group source of truth) in sync with CloudKit and surfaces every key back in the UI.

DEVICE REGISTRATION (PR #14) — Register button → CloudKit

RULE STATE — IOSRuleStore ↔ App Group ↔ CloudKit

PR #14 contract test. tests/IOSContractTests/CloudKitSchemaUsageTests.swift:5 reads FilterStatusModule.swift + BlockHandler.swift and FAILS the build if either uses a raw CloudKit literal instead of a GetBoredIdentifiers.CloudKit.* constant:
  • Banned literals: CKRecord(recordType:"…"), CKRecord.ID(recordName:"…"), record["devicesJSON"], or "iCloud.com.getbored.sync".

How to read getbored-ios

Hooks own async state

Three discriminated-union hooks. The two reads poll (5s / 3s); the registration write is one-shot. use*.ts

Bridges are classic RN modules

*Bridge.ts (JS guard + parse) → .m RCT_EXTERN_MODULE → Swift @objc. New Arch is on, but these stay bridge modules.

Swift collects, Kotlin decides

Every business decision routes through KMPDecisionCoreAdapter → GetBoredSharedCore; no framework → preconditionFailure.

One App Group, three enforcers

App Proxy + Data Provider + Control Provider share group.com.getbored.ios; the Flow Log card is a live tail of relay decisions; CloudKit syncs rules cross-device.
