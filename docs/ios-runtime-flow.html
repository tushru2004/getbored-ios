1. The whole shipped system

What the app stores

AccountModule.swift:46–87 writes only the returned session token. KeychainStore.swift:27–40 also stores the server device ID. The password is never persisted.

Who installs the profile?

FilterStatusModule.downloadProfile() opens an HTTPS download URL. The user completes Apple’s consent and installation flow in Settings; the app cannot silently install it.

site_rules · filter_mode · filter_exceptions · allowedAppBundleIDs · blockedAppBundleIDs.

Direct Data Provider decisions

FlowInspector.handleNewFlow() directly allows safe/system/allowed apps and directly drops explicitly blocked apps. Its outbound-data callback directly drops blocked TLS SNI or HTTP Host traffic.

Control Provider escalation

Blocked browser URLs and QUIC hosts return .needRules(). BlockHandler rechecks whether the app became allowed, then returns the final verdict.

Important process boundary

OSLogStore(scope: .currentProcessIdentifier) reads the containing app’s logs. It does not collect logs from the separate iOSFlowInspector or iOSBlockHandler extension processes.

No activity-history persistence

IOSActivityLogger is currently disabled in IOSRuleStore.swift:423–457. Calls remain in provider code, but the persistence methods are no-ops; there is no shipped customer-facing activity history.

Not in the release-1.0 runtime

These sources remain in the repository or Xcode project, but the App Store app does not embed or execute them as part of its shipped path.

CloudKit

Release policy comes from GET /api/policy. CloudKit login, device registration and cross-device policy sync from the old page were pre-release architecture.

Safari Web Extension

SafariChildRegistrationExtension remains as a separate target but is not embedded in the shipped app.

Safari App Proxy

SafariAppProxyProvider is a spike target and is not an App Store runtime dependency.

Whitelist / allow-list mode

Release 1.0 coerces this mode to blockSpecific; the old Safari parent-child allow-list route is unreachable.
