GetBored iOS — release 1.0 architecture

Username/password sign-in → production dashboard + REST API → device registration and policy sync → shared App Group → Network Extension filtering. iPhone only; release 1.0 enforces block-list mode. Live filtering requires a supervised iPhone, its managed Web Content Filter profile, and in-app enablement through Network Extension preferences.

App Review demo mode

A review_demo account bypasses the activation-code gate and the profile-install gate so sign-in, review-device registration, dashboard list assignment and rule synchronization can be exercised. It grants review access only — it never activates live filtering, and the app states that live filtering requires a supervised iPhone.

Filtering precondition

Live blocking requires a supervised iPhone, the managed Web Content Filter profile installed through Settings, and the in-app Turn Filtering On action that saves NEFilterManager preferences. Without the managed profile, iOS does not activate iOSFlowInspector or iOSBlockHandler, so an unsupervised review device performs no live blocking.

Not in release 1.0
